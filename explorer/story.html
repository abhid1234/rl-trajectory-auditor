The Pileup.

Fifty-one agents. Seventeen different codebases. The exact same trap.

We audited 5,000 real reinforcement-learning agent runs — coding agents trying to fix real bugs in real repositories. Each run is a trajectory: every command, every edit, every error message, sometimes two hundred turns long. Almost nobody reads these. We did.

And in the middle of the corpus, a pattern kept surfacing. Not similar. Identical.

str_replace_editor str_replace_editor str_replace_editor …and again. And again.

Edit the file. Edit the file. Edit the file. No running the tests in between. No reading a different file. No stepping back. Just the same move, over and over — the behavioral signature of an agent that has stopped diagnosing and started thrashing.

51 agents

in our curated set alone walked this exact three-move loop — across 17 unrelated repositories, from a serialization library to a welding-data toolkit.

one square = one stuck agent · average run length 126 turns, the longest 201

Zoom out to the full five thousand and it gets worse: 1,792 runs — 36% of the corpus — repeat a failing move-sequence that other agents in the same repo also got stuck on. These aren't random mistakes. They're shared ruts: decision points where the training distribution simply doesn't know what to do next, so every agent falls into the same hole.

An aggregate pass-rate will never show you a rut.
A trajectory will.

Here's the twist that makes auditing genuinely hard: the same three-edit loop doesn't always mean the same disease. Read the actual traces and the LLM judge splits them — some are a training gap (the agent thrashes when its plan fails), some are a harness bug (the environment silently rejected every edit, so looping was almost rational), and some are product routing. Same symptom, three different fixes. That's why you read.
